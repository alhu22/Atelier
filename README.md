# Atelier

Atelier runs one Python server for the sign-in page, administrator dashboard, website builder, and APIs. Google sign-in determines each user's workspace from their Firebase account and verified custom claims.

## Run locally

Install the frontend dependencies:

```sh
npm install
```

Build the frontend once and start the Python server:

```sh
npm start
```

Open http://127.0.0.1:5173/main. The root URL redirects to `/main`.
Sign in with Google: accounts with the Firebase `admin: true` custom claim go to
`/admin`; other accounts go to `/<their Firebase UID>` (for example `/abc123`).
Signed-out visitors cannot open protected workspaces. Builder users cannot open
`/admin` or another user's workspace; signing out returns to `/main`. Role checks
must finish successfully before either workspace is shown.
Python 3.10 or newer and Node.js 20.19+ (or 22.12+) are required.

Only Python serves the application after the build finishes; there is no Vite
development server and no generated website server running. Press Ctrl+C to stop.
`npm run dev` is an alias for this same single-server startup.

Once built, you can start only Python directly without rebuilding:

```sh
python3 server.py
```

Rebuild after changing frontend code or public Firebase configuration. No source
files, templates, browser-saved projects or Firestore projects are deleted by this setup.

The React client reads Firebase web configuration from a root `.env.local` file at build time. Add the Firebase project values below to enable Google sign-in, role-based routing, and cloud project access.

```dotenv
VITE_FIREBASE_API_KEY=your-firebase-web-api-key
VITE_FIREBASE_AUTH_DOMAIN=your-project.firebaseapp.com
VITE_FIREBASE_PROJECT_ID=your-project-id
VITE_FIREBASE_APP_ID=your-firebase-app-id
# Optional:
VITE_FIREBASE_MESSAGING_SENDER_ID=your-sender-id
VITE_FIREBASE_STORAGE_BUCKET=your-project.appspot.com
```

The Firebase web configuration is public client configuration. Never place the Azure OpenAI API key, GitHub OAuth secret, or service-account credentials in a `VITE_` variable.

## Project layout

- `server.py` starts the Python API server.
- `atelier_server/` contains server configuration, model generation, GitHub integration, and HTTP routes.
- `src/components/ui/` contains reusable controls; `src/components/` contains layout and feature components.
- `src/pages/Auth.tsx` is the shared `/main` sign-in page; `Dashboard.tsx` and `Index.tsx` provide the protected admin and user workspaces. `src/App.tsx` guards routes against the signed-in UID and verified role.
- `src/hooks/` contains auth, project, GitHub, and dashboard state.
- `src/integrations/` contains Firebase clients and API service adapters.
- `src/styles/globals.css` and `tailwind.config.ts` define the Tailwind theme and CSS variables.
- `dist/` is generated by `npm run build` and served by Python.
- `templates/react/` contains the actual website delivered to users, not the builder UI: the responsive Kebabhouse Karlskrona starter.
- `scripts/compile-project.mjs` typechecks and bundles generated source locally; it never executes generated package scripts or build configuration.

The server reads `MODEL_URL`, `MODEL_NAME`, and `API_KEY` from `.env`. For Azure OpenAI, set `MODEL_URL` to the resource's OpenAI v1 base URL, `MODEL_NAME` to the deployment name, and `API_KEY` to its key. The Azure key stays on the server and is never sent to the browser. Generation requests can wait up to five minutes for a response; asking for a smaller change can help if a request times out.

Chat uses `/api/chat`. Restart Python after backend changes; rebuilding the frontend does not reload a running Python process. For hot frontend development, run `npm run dev:api` and `npm run dev:web` separately. Both read the backend `PORT` from `.env` (default `5173`); Vite also accepts an explicit `API_PROXY_TARGET`.

Azure v1 URLs such as `https://your-resource.openai.azure.com/openai/v1` do not require `api-version`. Deployment-style Chat Completions URLs require `api-version` in the URL or `AZURE_OPENAI_API_VERSION`, and their deployment must match `MODEL_NAME`. Tool-enabled chat uses the Responses API for `gpt-6-astra`; this deployment rejects function tools through Chat Completions with reasoning enabled and also rejects `reasoning_effort: none`. Set `MODEL_API=responses` for an aliased deployment of that model, or `MODEL_API=chat` for a compatible Chat Completions model. `MODEL_REASONING_EFFORT` is optional and must be supported by the deployment.

Chat reserves `MODEL_MAX_COMPLETION_TOKENS` (default `16000`) from `MODEL_CONTEXT_TOKENS` (default `128000`); set these to your deployment's actual limits. It drops older conversation first, then omits whole files rather than sending truncated source. Files mentioned in the prompt take priority. Omitted files cannot be changed by that response, and unspecified files remain intact. Azure error bodies are logged server-side with credentials redacted, and the provider's message appears in the retryable chat card.

## Firebase setup and builder capabilities

The builder behavior below is available in each signed-in builder user's workspace.
Opening `/main` or administration does not create, migrate, generate or run website
projects. Route guards complement, but do not replace, the Firestore ownership
rules and admin custom-claim checks.

1. In Firebase Console, enable **Authentication → Sign-in method → Google**.
2. Create a **Cloud Firestore** database.
3. Deploy the Firestore rules and indexes from the repository root with `firebase deploy --only firestore --project atelier-6f995` after installing and authenticating the Firebase CLI.
4. In **Authentication → Settings → Authorized domains**, ensure `localhost` is listed for local development.
5. Restart Atelier and click **Sign in with Google**.

This setup targets Firebase's Spark plan and does not use Cloud Storage. Firestore stores each small project document under `users/{userId}/projects/{projectId}`, including metadata (name, owner UID, settings, entry page, and timestamps) and text file contents. Generation is limited to 100 files and 700 KB of text to stay below Firestore's 1 MiB document limit. Deploy the updated rules before syncing projects with more than 30 files. The rules restrict project access to the signed-in user who owns each project.

The model returns complete React/TypeScript source, with app startup and routing in `src/app/`, route components in `src/pages/`, shared primitives/layout/sections in `src/components/`, and Tailwind tokens in `src/styles/`. Hooks, services, integrations, types and utilities are added when used; no placeholder authentication, pages, database clients or services are created. The project includes Vite, strict TypeScript, matching `@/` aliases, Tailwind configuration, `components.json`, and its own dependency manifest and build scripts. Follow-up generation receives the full existing source and must preserve its architecture and functionality.

The file pane edits the delivered source. React previews compile the entire project even when a TypeScript or CSS file is selected. Preview uses the project's serializable `src/styles/theme.json` extension and CSS tokens, and an in-memory router inside the sandbox; exported projects use browser routing. Supported preview dependencies are React, React DOM, React Router and Firebase. Preview does not install arbitrary dependencies, execute generated configuration, or read server secrets/environment files. Custom build plugins, dynamically constructed public asset URLs, environment-dependent integrations and server-backed authentication may require running the exported project with its intended public configuration/backend. Import local assets from source where possible. Image upload remains unavailable on this Firebase plan.

New projects use `templates/react/` immediately. Opening an existing static project automatically requests a **separate `(React)` copy** from the configured model; the original project and its files remain saved. Successful migrations are checked for explicit legacy HTML routes, architecture, strict TypeScript errors and bundling errors before acceptance. An invalid model result gets one repair attempt. If migration fails or the source changes during the request, the original stays usable and a retry action is shown. Existing copies are not recreated on every open. Static previews and static follow-up edits remain supported, so migration failures do not force a destructive conversion. Model-generated migrations still require a functional review of project-specific behavior; compilation alone cannot prove arbitrary JavaScript behavior was preserved.

ZIP and GitHub exports contain the complete project source, not the builder or an HTML-only snapshot. After exporting, run `npm install`, `npm run typecheck`, and `npm run build` in the project directory. Deploy the resulting `dist/` with an SPA fallback to `index.html`. No credentials are needed for the included Kebabhouse starter; verify business details and connect ordering before publishing.

For local regression checks, run `npx playwright install chromium` once, then `npm run test:projects`. Tests cover the generator/API contracts, strict compilation, desktop/mobile browser rendering, routing, hooks, local SVG assets, ZIP contents and non-destructive migration/retry. They use mocked model responses and do not contact Firebase or the model provider. Run `npx tsc --noEmit -p tsconfig.app.json` and `npm run build` for the builder, and `npm --prefix templates/react run build` for the delivered website. No standalone lint command is configured.

To check project ownership rules and the 100-file limit locally, run `npx firebase-tools emulators:exec --only firestore --project demo-atelier-rules 'node --test tests/firebase-projects.test.mjs'` (requires Java 21 or newer). This uses a demo database, not production. Cloud saves preserve the existing creation timestamp exactly and replace legacy document fields with the current project schema.

The Projects link lists and opens projects belonging to the signed-in account; **New project** creates a separate project. Select **Delete** beside a project and confirm to permanently remove it from the workspace. Deleting the open project switches to another saved project, or starts a fresh unsaved project if none remain. Select the project name in the studio header to rename it; the updated name saves with the project locally and, when signed in, to Firestore. Older Firestore projects with file contents embedded in their documents remain compatible and are upgraded with owner/settings metadata when opened. Projects previously migrated to Cloud Storage require Storage to be enabled before they can be opened. Undo history remains local to that browser. Without signing in, projects continue to save in browser local storage.

**My profile** lets a signed-in user update their Atelier display name and profile photo URL; it does not change their Google account profile.

## View users, projects, and activity as an admin

1. Deploy [`firestore.rules`](./firestore.rules) and [`firestore.indexes.json`](./firestore.indexes.json) as described above.
2. In Firebase Console → **Authentication → Users**, copy the UID of the account that should administer Atelier.
3. In a trusted environment with Node.js and the Firebase Admin SDK available, grant that account the `admin` custom claim using Firebase Admin credentials. Keep service-account credentials outside this repository and never put them in browser code:

   ```js
   const admin = require("firebase-admin");
   admin.initializeApp({ credential: admin.credential.applicationDefault() });

   async function grantAdmin(uid) {
     const user = await admin.auth().getUser(uid);
     await admin.auth().setCustomUserClaims(uid, {
       ...user.customClaims,
       admin: true
     });
   }

   grantAdmin("PASTE_THE_AUTH_USER_UID_HERE")
     .then(() => console.log("Admin access granted."))
     .catch((error) => {
       console.error("Could not grant admin access.", error);
       process.exitCode = 1;
     });
   ```

4. Sign out of Atelier and sign back in through `/main` with the admin account. You are redirected to `/admin`. It shows account details, saved project metadata, and the latest 250 usage events. It does not display project file contents. Use **Refresh data** to reload.

The user dashboard loads at most 500 profile documents, 1,000 project documents, and 250 recent activity events per refresh. Users who have not signed in since profile recording was added may appear only if they have a project or activity document. This is an admin usage view, not a tamper-proof audit log.

Atelier records sign-in/sign-out, project creation/open, successful website generation, and ZIP/GitHub export events. Each activity record contains the user's Firebase email, event type, and server timestamp; prompts and project contents are not logged. A user's profile summary stores email, display name, photo URL, first-seen time, and last-seen time. Users can create and update only their own profile; Firestore allows cross-account profile, project, and activity reads only for authenticated users with the `admin` custom claim. Admin dashboard access does not grant permission to change another user's projects.

## Enable GitHub sign-in and export

GitHub sign-in requires a one-time OAuth App registration for this Atelier server:

1. On GitHub, open **Settings → Developer settings → OAuth Apps → New OAuth App**.
2. Set the homepage URL to `http://127.0.0.1:5173` and the authorization callback URL to match the `GITHUB_REDIRECT_URI` configured on the Python server. For Vite development, use `http://127.0.0.1:5174/api/github/callback`; for the production-style Python-served app, use `http://127.0.0.1:5173/api/github/callback`.
3. Copy the OAuth App client ID and generate a client secret. Add both to the server's `.env` file:

   ```dotenv
   GITHUB_CLIENT_ID=your-oauth-app-client-id
   GITHUB_CLIENT_SECRET=your-oauth-app-client-secret
   GITHUB_REDIRECT_URI=http://127.0.0.1:5174/api/github/callback
   ```

4. Restart the Python server, click **GitHub → Connect with GitHub**, review and approve GitHub's authorization, then search and select a repository. When serving the built app directly from Python, update both callback URLs to port `5173`.

The OAuth App requests GitHub's `repo` scope so it can write project files to selected private or public repositories. This scope grants access to the user's repositories, not just the one selected in Atelier; prefer a GitHub App if narrower per-repository permissions are required. The client secret and access token stay on the server, are never sent to browser JavaScript, and are held in server memory only. The browser receives an HttpOnly session cookie; restarting the local server ends the Atelier GitHub session. **Sign out from Atelier** clears that session; revoke the OAuth App itself from **GitHub Settings → Applications → Authorized OAuth Apps** if you want to remove its authorization. For a different port or server behind HTTPS, set the OAuth App callback URL and `GITHUB_REDIRECT_URI` to the same exact HTTPS callback address. Never commit `.env` or share OAuth secrets.

Firebase's web configuration is included in the client app as intended for Firebase web SDKs. Keep the Azure OpenAI API key and any service-account credentials out of browser code.
